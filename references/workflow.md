# 使用流程与输出规范

## 首轮提问

请使用者提供：

1. 城市
2. 行政区
3. 期望活动片区或夜生活区域
4. 人数范围
5. 期望总距离或最长步行时间
6. 目标便利店数量或范围

可选：起点、终点、环线/单向、夜生活优先、避开区域或品牌、是否需要 9:16 图片（默认需要）。

## 两次图片输出

第一张是三栏选择图：A/B/C 并列，地图简化但信息清楚，每栏展示路线特点、距离、时间、checkpoint 数量和适合人群。

第二张是用户选定路线的单路线图：沿用福田案例样式，地图在左、清单和路线亮点在右，底部放注意事项与便利店图例。地图上加入小型便利店 logo/店铺标识，但不得把近似标识解释为实时 POI 证明。

## 数据要求

正式运行前读取本机环境变量 `AMAP_API_KEY`。高德返回的地点、路线、道路和 POI 是事实来源；模型只负责路线风格组织、比较和图片排版。Key 不得出现在对话、输出文件或 GitHub。

路线必须从起点总体推进到终点：可以左右绕行以接近便利店目标，但不得走回头路、重复同一道路段或为了凑店铺数量反向返回。若目标数量与真实 POI 密度冲突，优先保证真实、顺路和终点正确，并说明实际数量。

正式规划顺序固定为：高德定位起点/终点 → 建立起终点之间的搜索范围 → 切分网格逐格搜索便利店 → 去重和过滤 → 用高德步行规划验证候选点顺序 → 组装不回头路线 → 评分 → 生成三方案图。不得从模型记忆或示意图反推店铺位置。

网格核验图阶段不做路线筛选：每个网格内高德返回的便利店候选都要标出来。只有用户确认 POI 分布后，才根据步行距离、主路线偏离和不回头规则选择 checkpoint。

路线选择采用动态逐点方式：从起点选择第一家合适的店；到达后，以当前位置和终点重新评估下一家店。每一步都优先选择继续向终点推进且不重复道路的候选，直到达到合理数量或继续增加会造成绕路。不得把所有 POI 一次性按直线距离排序。

## 福田回归基准

输入使用 `examples/shenzhen_futian.example.json`。应先输出三方案选择图，推荐 A；收到 A 后输出单独 A 线最终图。可使用 `examples/shenzhen_futian.expected.md` 和项目根目录案例图片进行人工视觉检查。
